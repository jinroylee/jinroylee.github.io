딥브레인 AI

AI 영상 생성 서버 안정화 프로젝트

Automation Server 2.0은 키워드, 상품 URL, 문서를 입력받아 영상을 자동 생성하는 서버입니다. Docs2Video 파이프라인을 개발했습니다. 파드 간 공유 rate limiter, FFmpeg 작업 분리, Job 유실을 막는 락으로 확장성 문제를 해결했습니다.

  • 0대규모 API 호출 시 429 에러
  • 30%+작업 처리 속도 향상
  • 2,000/h2시간 부하 테스트에서 유지한 요청량

문제와 목표

서버는 LLM, 웹 크롤러, 생성형 AI로 비디오 스크립트, 이미지, 배경 영상 등 필요한 요소를 자동 생성하고 조합합니다. 대규모 외부 API 호출과 CPU-bound 작업을 감당하면서 Job을 잃지 않고, 고부하에서도 안정적인 성능을 유지해야 했습니다.

주요 기여: Docs2Video

  • 사용자가 ppt, pdf, docs 등의 파일을 입력하면 텍스트와 이미지 추출
  • 추출한 정보를 LLM에 입력해 영상 구조 설계와 스크립트 생성
  • 파일에서 추출한 이미지와 내용에 맞게 새로 생성한 이미지를 같이 사용해 영상 자동 제작

주요 기술 결정

모든 파드가 공유하는 rate limit

외부 API에는 RPM/TPM 제한이 있는데, 각 파드는 자기 호출량만 알고 있었습니다.

  • Redis Pub/Sub 기반 Rate-Limit Queue 클래스를 개발해 모든 파드가 동일한 rate limit을 공유하도록 설정
  • 5초 단위 sliding window로 호출량 계산
  • 각 파드는 채널 정보와 자체 상태를 조합해 태스크 실행 여부를 판단

성과: 대규모 API 호출 시 rate limit 초과로 인한 429 에러가 0건이었습니다.

CPU-bound FFmpeg 작업 분리

  • Prometheus 모니터에서 CPU 사용량 급증 관측
  • 기존 Agenda 큐에서 FFmpeg 태스크를 대량으로 처리할 때 병목 발생
  • FFmpeg 태스크를 별도 BullMQ 큐로 분리, concurrency=1과 hostname 체크로 파드마다 한 번에 작업 하나만 수행하도록 설정

성과: 전체 Job 처리 속도가 30% 이상 개선됐습니다.

Redlock으로 Job 생성 직렬화

  • Agenda 큐에 Job을 대량 등록할 때 일부 Job이 유실되는 현상 발생
  • Redis 기반 Redlock 알고리즘 도입: Job 생성 직전에 락 획득, 큐 등록 직전에 해제
  • Job이 큐에 들어가기 전에 직렬화되는 효과를 냄

성과: Job 유실을 100% 해결했습니다.

검증

Puppeteer 기반 UI 부하 테스트를 설계했습니다. EC2 m4.2xlarge 인스턴스마다 PM2 프로세스 4개와 브라우저 4개를 띄워 시간당 2,000 요청을 2시간 연속 시뮬레이션했습니다. 서버 안정성이 유지됐고 새로 추가한 큐들도 정상 동작했습니다. Job 처리율 95% 이상, 실패율 1% 미만을 유지했습니다.
