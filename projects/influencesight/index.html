InfluenceSight: social-media engagement prediction model

Scores the likely advertising value of a social media post. A CLIP-based model fine-tuned with LoRA predicts an engagement score from the image, caption, and comments; data collection, retraining, and serving are automated with AWS, RunPod, and Airflow, so the model stays current.

Model

Only the LoRA adapters and the small regression head are trained; both CLIP encoders stay frozen.
  • Multimodal features. CLIP ViT-L/14 image and text encoders produce 768-dimensional embeddings for the image and caption. A sentiment score from the top five comments is added, giving a 1,537-dimensional feature.
  • Regression head. A shallow MLP trained with Huber loss predicts the engagement score.
  • Efficient fine-tuning. The CLIP weights stay frozen and only LoRA adapters (about 2.6M trainable parameters) are trained, saving memory and time and limiting the risk of overfitting.

Labelling the data

There is no ground-truth “engagement score”, so I defined one:

  • Normalise by views. like_rate = L/V, comment_rate = C/V, share_rate = S/V, so reactions are measured relative to exposure.
  • Weight by intent. Shares count more than comments, and comments more than likes.
  • Reward reach, but not size. reach_boost = log10(V+1) / log10(F+1), where F is the follower count, dampens the bias toward large accounts.
Score_raw = (wL·L/V + wC·C/V + wS·S/V) · log10(V+1) / log10(F+1)

Training and serving pipeline

Collection (Lambda), training (RunPod, triggered by Airflow), and serving (FastAPI on ECS Fargate) exchange data only through S3.
  • Collection. An AWS Lambda function collects new data and stores it in S3.
  • Training. Containerised training code runs on RunPod Serverless and only starts when requested. Images are loaded lazily from S3 in the PyTorch dataset’s __getitem__ to avoid CUDA out-of-memory errors.
  • Orchestration. An Airflow DAG runs preprocessing → training → evaluation → artifact upload on the data in S3.
  • Serving. FastAPI on ECS Fargate serves predictions over a REST API; models, features, and logs live in S3.
